# Harness-стартер: три файла, после которых агент перестаёт врать про свою работу

Шаблон среды для проекта, в котором работает ИИ-агент (Claude Code, Cursor, Codex).
Не библиотека и не фреймворк - три текстовых файла и одна проверка. Подключается
к любому проекту на любом стеке за 10 минут.

## Зачем

Агент на большом проекте к третьему дню ломает то, что работало вчера, и уверенно
докладывает, что всё отлично. Причина не в модели и не в промпте: **у агента нет
способа узнать, работает ли написанное, если проект не даёт обратной связи.** Он
отчитывается о намерении.

Harness даёт проекту голос: статус «работает» - это не слово агента, а строка в
реестре со ссылкой на прогон проверки.

## Что внутри

| Файл | Задача |
|---|---|
| `AGENTS.md` | Карта проекта: команда старта, команда проверки, жёсткие ограничения. Оглавление, не энциклопедия |
| `CURRENT_STATE.md` | Проверенное состояние: активная фича, последняя проверка с результатом, блокер, следующий шаг |
| `plans/feature_list.json` | Реестр фич: поведение, команда проверки, статус, ссылка на доказательство |
| `plans/2026-09-05-пример-фичи.md` | Образец подробного плана одной фичи |
| `tools/check_harness.py` | **Единственная проверка стартера** - валидирует сам harness |
| `CLAUDE.md` | Указатель на `AGENTS.md` для Claude Code, чтобы не было двух наборов правил |

## Подключить к своему проекту за 10 минут

1. Скопируй `AGENTS.md`, `CURRENT_STATE.md`, `plans/`, `tools/`, `CLAUDE.md` в корень проекта.
2. В `AGENTS.md` замени команды старта и проверки на **реальные** - те, что запускаются
   у тебя сейчас. Не «должно бы», а «прогнал, работает».
3. В `plans/feature_list.json` опиши одну первую фичу со статусом `not_started`.
4. Запусти `python3 tools/check_harness.py` - он должен быть зелёным.
5. Дальше агент входит в проект, читает три файла и знает правду.

## Четыре правила, без которых harness не работает

1. **Статус `passing` только после проверки с доказательством.** Пустое поле `evidence`
   при статусе `passing` - проверка падает.
2. **Одна фича в статусе `in_progress`.** Две - проверка падает.
3. **Красная база блокирует новую фичу.** Сначала чинить, потом начинать.
4. **`AGENTS.md` короткий.** Разросся - агент перестал читать.

## Проверить, что стартер сам себе harness

```bash
python3 tools/check_harness.py
```

Ожидаемо: `HARNESS OK` и код выхода 0. Это и есть та самая «одна проходящая проверка»,
с которой начинается любой новый проект.
